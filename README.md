# CV → 多模态：目标检测与论文复现

> 面向计算机科学与技术专业本科阶段的长期学习、项目实践、论文复现与研究生复试准备。
>
> **核心主线：CV → 目标检测 → Transformer → Open-Vocabulary Detection → Vision-Language → 多模态**

---

## 1. 项目定位

本仓库用于系统记录一条从**计算机视觉（Computer Vision, CV）**逐步走向**视觉语言与多模态学习（Vision-Language / Multimodal Learning）**的学习与实践路线。

本项目不是以“记住知识点”或“完成若干代码练习”为最终目标，而是逐步建立以下能力：

1. 理解计算机视觉与深度学习的核心原理；
2. 能够理解 CNN、目标检测、Transformer 等模型的基本结构与工作机制；
3. 能够阅读和修改开源深度学习代码；
4. 能够完成目标检测任务的完整实验流程；
5. 能够解释数据预处理、模型选择、训练参数和评价指标背后的原因；
6. 能够阅读计算机视觉方向论文；
7. 能够复现开源论文的核心实验；
8. 能够进行数据集迁移、消融实验和小规模改进；
9. 最终建立进入视觉语言模型和多模态方向的基础；
10. 将学习和项目成果整理为可用于研究生复试/导师面试的项目材料。

# 5. 项目 1：目标检测开源竞赛项目

## 5.1 项目定位

项目 1 的核心目标不是“刷榜”，也不是简单地复制别人的代码，而是通过一个已经结束的 Kaggle / 天池目标检测比赛，建立完整的深度学习项目能力。

### 基本路线

```text
比赛选择
   ↓
阅读比赛说明
   ↓
了解数据集
   ↓
数据分析与可视化
   ↓
建立 Baseline
   ↓
运行公开高分方案
   ↓
分析高分方案
   ↓
理解数据处理与模型
   ↓
自行设计实验
   ↓
比较实验结果
   ↓
分析结果
   ↓
形成项目报告
```

## 5.2 必须掌握的内容

### 数据

- 数据集结构；
- 类别数量与分布；
- 图片尺寸；
- 目标数量；
- 小目标/大目标分布；
- 类别不平衡；
- 标注质量；
- 训练集 / 验证集划分；
- 数据增强。

### 模型

至少理解：

- Backbone；
- Feature Map；
- Neck；
- FPN / 多尺度特征；
- Detection Head；
- Loss；
- 推理；
- NMS。

### 训练

能够解释：

- Batch Size；
- Learning Rate；
- Optimizer；
- Epoch；
- Weight Decay；
- 数据增强；
- 输入分辨率。

### 评价

能够解释：

- IoU；
- Precision；
- Recall；
- F1；
- AP；
- mAP；
- mAP@50；
- mAP@50:95（根据具体项目所采用指标进行理解）。

## 5.3 项目完成标准

不能停留在：

```text
下载代码
   ↓
运行成功
   ↓
结束
```

最低要求：

```text
跑通代码
   ↓
理解数据处理
   ↓
理解模型结构
   ↓
理解训练参数
   ↓
理解评价指标
   ↓
完成至少 3～5 组自己的实验
   ↓
分析实验结果
   ↓
形成完整项目记录
```

# 6. 项目 2：论文复现项目

## 6.1 项目定位

项目 2 用于从“工程实践”过渡到“科研实践”。

论文方向优先考虑：

- Open-Vocabulary Object Detection；
- Vision-Language Model；
- 目标检测与视觉语言结合；
- 与视觉语言/多模态自然衔接的计算机视觉方向。

**最终论文不会在路线开始时强行固定。**

选择论文时需要综合考虑：

- 与当前学习路线的衔接；
- 是否有公开代码；
- 仓库维护情况；
- 依赖环境是否能够配置；
- 所需 GPU 资源是否适合当前条件；
- 是否能够复现核心实验；
- 是否具有清晰的实验设计；
- 是否适合作为本科阶段复试科研项目。

## 6.2 论文复现流程

```text
论文筛选
   ↓
阅读 Abstract / Introduction
   ↓
理解研究问题
   ↓
阅读方法与模型结构
   ↓
分析实验
   ↓
阅读官方代码
   ↓
配置环境
   ↓
运行官方示例
   ↓
复现核心结果
   ↓
分析与论文结果的差异
   ↓
迁移到其他数据集
   ↓
消融实验 / 小规模改进
   ↓
形成复现报告
```

## 6.3 论文复现的核心标准

不能停留在：

> “官方代码成功运行。”

应该做到：

- 知道论文解决什么问题；
- 知道过去的方法有什么不足；
- 能解释论文提出的方法；
- 能解释关键模块为什么存在；
- 能读懂主要源码；
- 能复现核心实验；
- 能解释复现结果与论文结果的差异；
- 能尝试迁移到其他数据集；
- 能开展消融实验或小规模改进。

# 7. 从 CV 走向多模态

项目 2 的设计重点不是单纯再做一个目标检测项目，而是建立：

```text
目标检测
   ↓
开放词汇目标检测
   ↓
文本提示
   ↓
视觉特征 + 文本特征
   ↓
Vision-Language
   ↓
多模态
```

因此需要逐步理解：

### Transformer

- Token；
- Embedding；
- Query / Key / Value；
- Self-Attention；
- Multi-Head Attention；
- Positional Encoding；
- Encoder / Decoder。

### Vision-Language

- Visual Encoder；
- Text Encoder；
- Visual Feature；
- Text Feature；
- Feature Alignment；
- Similarity；
- Text Prompt；
- Open-Vocabulary Detection。

### 多模态

在完成前面的基础之后，再逐步接触：

- Vision-Language Model；
- 多模态表示；
- 图像-文本对齐；
- 视觉语言任务；
- 多模态大模型。

# 13. Git 管理原则

Git 用于记录：

> **代码和项目资料的版本历史。**

`.gitignore` 用于排除：

- Python 缓存；
- IDE 本地配置；
- Conda / 虚拟环境；
- 原始数据集；
- 处理后的大数据集；
- 大型模型权重；
- 训练输出；
- 日志；
- 临时文件；
- 本地敏感配置。

不应因为使用 Git 就把大型数据集和模型权重直接提交进仓库。

### 提交建议

每完成一个具有明确意义的阶段就进行一次 commit，例如：

```text
Initialize CV multimodal learning project
Day01: learn IoU and Conv feature map
Day02: implement NMS
Day03: understand AP and mAP
...
Project1: add baseline
Project1: add augmentation experiment
...
Project2: reproduce baseline
Project2: add dataset transfer experiment
```

`.gitignore` 本身应该提交到 Git。


### 原则 2：不盲目追求 SOTA

项目的目的不是为了获得一个看起来很高的指标，而是建立：

> **理解问题 → 设计实验 → 分析结果**

的能力。

### 原则 3：不把 AI 当作代码生成器

AI 是：

> 学习助手、解释器、代码审查者、实验讨论伙伴。

最终必须能够用自己的语言解释项目。

### 原则 4：路线可以调整，但主线不随意改变

允许因为：

- 基础薄弱；
- 环境问题；
- 论文复现难度；
- GPU 资源；
- 项目可复现性；

而调整具体任务。

但总体主线保持：

> **CV → 目标检测 → Transformer → Open-Vocabulary Detection → Vision-Language → 多模态**

### 原则 5：以真正掌握作为进入下一阶段的条件

不是：

> “日历到了 Day05，所以进入 Day05。”

而是：

> **达到当前阶段的验收标准，才进入下一阶段。**

---

# 19. 最终目标

完成这条路线后，希望达到的状态不是：

> “我做过两个 GitHub 项目。”

而是：

> **我能够从目标检测任务出发，独立理解数据、模型、训练和实验；能够阅读和复现计算机视觉论文；能够把模型迁移到新的数据集并进行实验分析；并能够进一步理解视觉语言和多模态模型。**

最终形成：

```text
基础
 ↓
项目
 ↓
论文
 ↓
实验
 ↓
科研思维
 ↓
复试表达
 ↓
研究生阶段进一步深入
```
